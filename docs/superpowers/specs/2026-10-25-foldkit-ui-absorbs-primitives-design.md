# Foldkit UI absorbs wseffect headless adapters — design specification

**Status:** Design authorized by the director's rulings in the task brief; implementation is not part of this turn. **Goal:** move all six `packages/primitives/src` capabilities into the owned `@wsagency/wseffect-foldkit-ui` package, and make DataTable consume a generalized VirtualList view. `@wsagency/wseffect-primitives` is deleted once its modules have moved; no compatibility package or export shims remain. Foldkit UI remains headless; all `rt-*` styling and Radix2Solid parity remain in Themes.

## Contract and approach

Implement the six capabilities as native Foldkit UI modules, not themes-specific wrappers inside the library. Extend `Menu`, `Slider`, `Tooltip`, and `Listbox` respectively, because they own the interaction/model/view semantics that these capabilities need; expose `CheckboxGroup` as an additional controlled view module; extend `VirtualList.view` with element overrides. Preserve existing default APIs/markup and behavior whenever the option is omitted. New local APIs follow Foldkit's Schema-backed `Model`/`Message`, `init`, `update`, `view`, and generic `create` conventions. Configuration and input records are typed and serializable where they belong in Models; closures and HTML remain view/config inputs, never Schema fields.

### APIs and migration by capability

No aliases remain under the old package name. Update every caller, root/workspace manifest, scripts, README/package listings, docs, consumer tests, coverage manifest, lockfile and packed surface. If removal of those manifests/modules leaves `packages/primitives` empty, delete the package directory and remove it from the workspace entirely; it has never been published.

## Tests, parity, and acceptance

Move the existing six primitive test families (Story/update/message/schema, Scene/ARIA, reuse, and SelectPosition lifecycle coverage) into Foldkit UI beside the owning modules. Add the regressions listed in the table plus package export/build identity and packed-consumer coverage for each new public subpath. Preserve existing Themes behavior/DOM snapshots and parity fixtures; extend the parity matrix only where public element shape changes are intended (none are intended). End-to-end and browser tests retain exact current acceptance, including 236/236 visual comparison; any difference is a regression, not an allowance. Foldkit UI UPSTREAM.md records every deliberate divergence and rationale; each of the six `docs/upstream` proposals is marked `Implemented locally in packages/foldkit-ui/...` and whether an upstream PR is worthwhile/optional.

## Risks and mitigations

- **Behavior/DOM drift:** centralizing behavior changes ownership and can perturb event ordering, focus restoration, menu markup, or select item layout. Move the existing test vectors before implementation; assert current public themed DOM and 236/236 visual comparison.
- **VirtualList structural assumptions:** nested table rows break direct-child lookup or measurement/scroll alignment. Test nested keyed lookup across ApplyScroll, anchor preservation, focus, and dynamic measurement; keep `ul`/`li` default regression.
- **Bundle/API impact:** new UI subpaths or Floating UI wiring can make unused code eager. Keep exact subpath exports, tree-shake and validate packed consumer closure, `gate:size --app apps/gallery`; no `rt-*` code enters Foldkit UI.
- **Test gaps after deletion:** losing package-local tests might lose adapter lifecycle, Story coverage or packed export checks. Move before deleting and make consumer coverage manifest assert each public entry. Run full `check`, e2e, consumer, size, and visual gates after integration.
- **Package cutover:** stale workspace references, aliases or docs can retain dependency. Search manifests and call sites, remove package from every inventory and test manifest, then packed consumer verifies no primitives import.

## Scope

No Radix styles/classes or Themes code move into Foldkit UI. No upstream acceptance is a dependency; proposals are optional. All six adapter capabilities move, and DataTable uses element overrides. No other component APIs or behaviors change.
