# Foldkit UI absorbs wseffect headless adapters — design specification

**Status:** Director-authorized design; this document and plan are read-only design work. **Goal:** move all six `packages/primitives/src` capabilities into owned `@wsagency/wseffect-foldkit-ui`, migrate DataTable's table-windowing view onto `VirtualList.view`, and delete the never-published `@wsagency/wseffect-primitives` package. Foldkit UI remains headless. Themes retains every `rt-*` class and exact Radix2Solid markup/visual parity.

## Code-grounded decisions

Inspected the primitive implementations/tests, their six Themes wrappers and their Story/Scene/reuse tests, Foldkit UI Menu, Slider, Tooltip, Listbox, Select and Checkbox modules/tests, VirtualList renderer/tests, and DataTable's renderer/mount/tests. Existing conventions include Schema-backed `Model`/`Message` and `create<T>()` bundles; config and VNodes stay outside serializable models. The target updates those modules in their existing style, not by copying whole adapters.

**Existing `select` name collision:** `packages/foldkit-ui/src/select/index.ts` is already an exported stateless native `<select>` attribute/view helper (`ViewConfig`, `SelectAttributes`, `view`). It is not a popup listbox and must remain unchanged. The new popup adapter gets the unambiguous `@wsagency/wseffect-foldkit-ui/listboxSelect` subpath/module. It composes the existing `listbox` API. It must not replace or alias `./select`.

## API decisions

### Menu context invocation

Extend `menu` and its generic `create<Item>()` bundle; do not fork Menu as ContextMenu. Export `ContextInvocationSchema = Schema.Struct({ invocation: Schema.Literals(['pointer','keyboard','touch']), sourceId: Schema.String, sourceToken: Schema.String, point: Schema.optional(Schema.Struct({x:Schema.Number,y:Schema.Number})) })`; `OpenedAtSchema`, `LongPressExpiredSchema = Schema.Struct({_tag:Schema.Literal('LongPressExpired'),version:Schema.Number})`, and `SourceUnmountedSchema = Schema.Struct({_tag:Schema.Literal('SourceUnmounted'),token:Schema.String})`; union all three into `Menu.Message`; export their inferred types and `openAt(model, invocation)`. Match the existing adapter's serialized `invocation` field name. The Menu view gets optional typed context-trigger inputs (`sourceId`, `sourceToken`, `longPressMs`, default 600ms) and a `ContextTrigger` Mount for native contextmenu, keyboard ContextMenu/Shift+F10, and touch lifecycle. Pointer/touch use Floating UI virtual point anchors; keyboard uses the invoking source. Close/selection/outside/Escape paths filter fixed `FocusButton`/`FocusItems`; `FocusSource` verifies a mounted `data-context-source-token` matches before restoring focus.

**Exact model schema compatibility:** add `maybeContextInvocation: Schema.optionalWith(Schema.Option(ContextInvocationSchema), { default: () => Option.none() })` and `longPressVersion: Schema.optionalWith(Schema.Number, { default: () => 0 })` to `Menu.Model`. `init` always writes both defaults. These are optional-on-decode with defined defaults, so old DropdownMenu/Menu page models decode. Do not change `Animation.Model` or existing Menu fields. Add a codec test that removes both new keys from an encoded legacy Menu model, decodes it, asserts `Option.none()`/`0`, then round-trips the decoded model and an invocation Message. Source identity stays serializable; no Element/function enters Model.

### Slider.Range

Add `Slider.Range` in existing `slider` module/API, alongside and without changing scalar Slider. Reuse existing Slider helpers for snapping/range constraints, DOM event attribute style and Subscription/Command conventions where possible. Public types: `Thumb = { id:string; value:number; min?:number; max?:number; step?:number }`; `RangeConfig = { min:number; max:number; step:number; orientation:'horizontal'|'vertical'; thumbs:ReadonlyArray<Thumb>; isDisabled?:boolean }`; Schema-backed `RangeModel = { activeThumbId:string|null; dragStartValues:ReadonlyArray<Thumb>|null }`; `RangeMessage` union `FocusThumb | Step | Page | SetBoundary | DragStart | DragValue | DragEnd | CancelDrag`; `RangeOutMessage.ValuesChanged({thumbs})`; `range.init(config)`, `range.update(model,config,message)`, `range.view(model,config,h)`. Parent owns values, IDs are stable, thumbs do not cross, bounds/steps compose with global range. Existing range uses Escape to cancel an active pointer drag, preventing default and emitting `CancelDrag`; release commits, pointercancel cancels.

### Tooltip group

Add explicit `tooltip/group` subpath rather than global or per-Tip hidden shared state. API: `GroupConfig={openDelay:number;skipDelay:number}`, Schema-backed `GroupModel` and `GroupMessage` (`TooltipOpened`, `TooltipClosed`, versioned `SkipExpired`); `group.init(config?)`, `group.update(model,message)`, `group.reflectShowDelay(model,config):number`. Defaults remain 700ms and 300ms. Tooltip Themes wrapper uses the group's effective duration as existing Tooltip `showDelay`, and folds each Tooltip's `Shown`/`Hidden` OutMessage into parent group state. The group is parent-owned and group instances do not affect one another.

### Listbox selected-item anchor and item content

Extend `listbox` (`shared` anchor Mount and single-select view) with `anchorMode?: 'Trigger'|'SelectedOrActiveItem'` in `InitConfig`, default `'Trigger'`. Add to `BaseModel` exactly `anchorMode: Schema.optionalWith(Schema.Literals(['Trigger','SelectedOrActiveItem']), { default: () => 'Trigger' })`; `baseInit` writes the default or configured value. This is the only Listbox model shape change: selected value is parent-owned and the selected/active item DOM id is derived from current view inputs. Legacy Listbox/DropdownMenu and Select models decode without the field; add legacy-missing-field codec test and new-model/message round-trip. The `AnchorListbox` Mount resolves the active item when present, otherwise the selected item, and falls back to the trigger if neither exists. Item-aligned positioning follows the active option as keyboard navigation changes, matching the current Select adapter. Widen `ItemConfig.content` from `Html` to `Html | ReadonlyArray<Html>` and render as sibling children, retaining single-Html behavior.

Add `listboxSelect` (`createSelect<Value>()`) as a thin typed adapter over Listbox with `SelectItem`, `SelectGroup`, `SelectSeparator`, `SelectOption`, `Config` and `Bundle`. Keep `position:'popper'|'item-aligned'`; `popper` uses trigger anchor and `item-aligned` selects `anchorMode:'SelectedOrActiveItem'`. Both use same Listbox state/view; remove duplicate item-aligned renderer and the separate Mount helper. This preserves active-item positioning, selected fallback, existing native `./select` exports and avoids a breaking export collision.

### Controlled CheckboxGroup

Add `checkboxGroup` as a stateless composition helper over the existing `checkbox` API, not as markup-only `view(props,h)`: `Option<Value extends string> = { value: Value; label: Html; isDisabled?: boolean }`; `Props<Value,Message> = { id: string; label?: Html; ariaLabel?: string; options: ReadonlyArray<Option<Value>>; selected: ReadonlySet<Value>; isDisabled?: boolean; toggleMessage(value: Value, isChecked: boolean): Message; toView(input: { rootAttributes: ReadonlyArray<ChildAttribute>; labelAttributes: ReadonlyArray<ChildAttribute>; options: ReadonlyArray<{ option: Option<Value>; checkbox: CheckboxAttributes<Message> }> }): Html }`; `view(props,h):Html`. It derives each checked/disabled toggle bundle through `checkbox.view` (including its role, state and keyboard semantics) and returns those attribute bundles to `toView`; callback owns DOM composition. Parent owns values; Foldkit supplies no RT classes. Themes `CheckboxGroup` uses `toView` to retain its labelled `<div role=group>`, label/input structure and classes; CheckboxCards uses the same controlled checkbox bundles inside its card markup, retaining button/card structure and classes.

Rationale: the existing Themes group/cards render visual buttons and card composition, while the old primitive renders checkbox inputs; a fixed Foldkit markup view would change the live DOM. Callback composition reuses Foldkit Checkbox semantics without prescribing Theme markup.

### VirtualList element/window API and DataTable

- `containerElement?: Exclude<TagName,'textarea'>` (default `'ul'`), `containerRole?: 'list'|'grid'|null` (default `'list'`), `rowElement?: ...` (current default `'li'`), and `rowRole?: 'listitem'|'row'|null` (default `'listitem'`). DataTable sets `containerRole:null` because its `role="grid"` belongs on the table inside the scrolling div. When `rowRole` is not `'listitem'`, omit list-only `aria-setsize`/`aria-posinset`.

- `rowToView?: (item,index,key,rowAttributes,h)=>Html` for callers needing semantic keyed rows; default remains today's keyed `rowElement` containing `itemToView`. Callback MUST preserve the supplied key and virtual-list data attributes in the returned row.
- `spacerToView?: (edge:'top'|'bottom',heightPx:number,h)=>Html`; defaults retain current keyed `li` spacer. DataTable returns a keyed, `aria-hidden` `<tr data-virtual-list-spacer=...><td colSpan={visibleColumnCount + selectionColumnCount} style="height: Npx; padding:0; border:0"></td></tr>`; the height-bearing `td` is required to keep table layout across browsers.
- `windowToView?: (window:{topSpacer:Html; rows:ReadonlyArray<Html>; bottomSpacer:Html; startIndex:number; endIndex:number; itemCount:number},h)=>Html`. Default concatenates spacers/rows; DataTable supplies `<table><caption/><thead/><tbody>{topSpacer,rows,bottomSpacer}</tbody></table>`. VirtualList remains the owner of the scroll viewport and Mount; its `containerElement:'div'` outer node carries `model.id`, overflow, scroll and resize behavior.

`ApplyScroll`, anchor preservation, row measurement and focus targeting must query keyed descendants (`[data-virtual-list-item-key]`) within the actual scroll container, not direct children. Keep key/index attrs on `tr` returned by `rowToView`; no index-based keys.

**Concrete DataTable tree:** `<div id=virtualList.id class="wse-data-table__scroll …" style="overflow:auto;max-height:360px" [VirtualList Observe Mount]><table class="wse-data-table …" [grid attrs/key handling]><caption/><thead class="rt-TableHeader" style="position:sticky;top:0;z-index:…"><tr>…header cells…</tr></thead><tbody class="rt-TableBody"><tr top spacer/><tr keyed data row/><tr bottom spacer/></tbody></table></div>`. Only `<tbody>`'s windowed rows/spacers change; caption and sticky header remain mounted. Preserve `rowViews` bounded LRU (refresh recency, evict beyond rendered window capacity); VirtualList window provides visible keyed rows and DataTable row renderer supplies `<td>` content/ARIA. Grid role/row/column indices and exactly one active cell `tabindex=0` remain unchanged; selection checkbox remains `tabindex=-1`. Preserve active `{rowId,columnId}` and focus recovery by row identity.
Remove `ScrollDataTableRow` command in `data-table.mount.ts`: DataTable update calls `VirtualList.scrollToKey(model.virtualList,rowId,{alignment:'Nearest'})` or `scrollToIndex` for a removed-row fallback, maps child commands to `Message.VirtualList`, and records pending focus. `VirtualList.ApplyScroll` waits on `Render.afterCommit`, scrolls to its logical target and emits `CompletedApplyScroll(Applied)`. On that child completion, DataTable schedules a typed `FocusDataTableCell` command. After commit it resolves the nested keyed `<tr>`, queries the target cell, and focuses only when the cell has `tabindex=0`; on success it sends new Schema-backed `Message.FocusTargetCompleted({rowId,columnId,scrollTop,scrollHeight,containerHeight,anchor})`. DataTable update accepts that message only for the matching `pendingFocus`, applies its snapshot through `VirtualList.update(ObservedContainerScroll(...))`, then clears pending focus. If the keyed row/cell is absent, do not send success; keep the pending target for the next committed window. Header focus stays a separate after-commit header-cell command. Add message codec coverage for `FocusTargetCompleted`. No second local row-windowing range/spacer computation.

## Risks and acceptance

- Model codec regression: old serialized Menu/Listbox data lacks new optional fields; defaulted optional schemas and explicit legacy-shape tests required.
- Context Menu behavior/focus drift: preserve event `defaultPrevented`, stale timer and token checks; test mounted-source and source-unmount flows.
- `listboxSelect` must not overwrite native `./select` export; packed consumer tests import/assert both subpaths.
- Table HTML validity and platform row sizing: `<td colspan>` required for spacer height; test real browser engines and exact existing visual matrix.
- VirtualList custom rows must retain keyed data attrs so nested ApplyScroll/measurement/focus and LRU reuse remain stable.
- Package closure: exact subpath imports, packed consumer and Gallery size gate must show no eager/unrelated UI closure.

Acceptance preserves behavior, DOM and visual parity, including compare-sp2 **236/236**, Themes tests/parity matrices, one full e2e, packed consumer and browser checks. No Foldkit upstream response is required; all RT classes remain local. No unrelated component changes.
